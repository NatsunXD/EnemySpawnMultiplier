Enemy Spawn Multiplier - v16 and v16.11 preview packages

Close the game before upgrading. Remove previous Enemy Spawn Multiplier entries
and install exactly one package:

- Enemy-Spawn-Multiplier-6x-Native-Composition-v16.zip
- Enemy-Spawn-Multiplier-6x-Light-Medium-Bias-v16.zip
- Enemy-Spawn-Multiplier-Preview-Low-Budget-Fast-Cadence-v16.11-preview.zip

Install and enable the official Bingus Shared Loader v15 or newer, deploy with
HDArsenal or HD2MM, and restart the game. All packages use the same resource ID
and cannot be combined.

What changed in v16.11
----------------------

v16.10 shortened the enemy reinforcement cooldown and the patrol refresh cooldown
and both were confirmed in game, but patrol squads stayed the same size. The
cause was that the three curves v16.10 scaled are a cooldown, a cooldown rate,
and a patrol *count* - none of them is units per squad.

Patrol squad size comes from a separate patrol-only curve:

    game.dll+0x943E40:
        xmm7 = cfg[curve_index + 0x3F8]      travelers_max_unit_count_multiplier
        xmm6 = cfg[curve_index + 0x3BC]      travelers_waves_cooldown_multiplier
        count = round(base_units * xmm7)
        cooldown_seconds -> [rsi]

v16.11 therefore also multiplies cfg+0x3F8 by 3.0. That is the only curve the
game uses to scale how many units a patrol wave contains.

Full curve set now scaled by 3.0 in this profile:

- cfg+0x164  encounter_cooldown_rate_modifier       enemy reinforcement cooldown
- cfg+0x1A0  patrol_count_max_modifier              how many patrols may exist
- cfg+0x1DC  patrol_spawn_cooldown_rate_modifier    patrol spawn cooldown
- cfg+0x3F8  travelers_max_unit_count_multiplier    units per patrol wave

Each block keeps its own baseline so a second pass cannot stack, and if the game
re-blends a curve for a new difficulty the freshly blended native value becomes
the new baseline and is scaled once from there.

Unchanged: reinforcement budget 0.1x with the effective cfg+0x78 override forced
to the scaled base, timed Patrol/Straggler intervals at 0.0-0.1 seconds (inert on
this build but correct if the branch is ever reached), nonzero per-type caps and
the group clamp at 10x, GuardForce/static defenders fully native.

Side effect to expect
---------------------

travelers_max_unit_count_multiplier is patrol-specific, so it should raise only
patrol squad size. If you also want outpost or guard-force squads larger, that is
a different curve:

- cfg+0x290  spawner_spawn_count_modifier          units per spawner wave
- cfg+0x218  spawner_queue_limit_modifier          production queue depth
- cfg+0x2CC  spawner_spawn_count_minimum_modifier  minimum units per wave

Those apply to every spawner, not only patrols, which is why they are not in the
preview yet.

Reading the log
---------------

- mv=  live head float of each scaled curve after the write; with a baseline of
       1.0 and a scale of 3.0 this reads 3.00/3.00/3.00/3.00.
- ms=  the applied scale quadruple, expected 3.0/3.0/3.0/3.0.
- p=   Encounter budget current/original, expected 60.0/600.0.
- o=   effective cfg+0x78 override, expected 60.00.
- e=, a=, b=, d=, fl=  the reinforcement deadline and timed-scheduler gate inputs.

To uninstall, close the game, disable this mod, purge deployment, and redeploy
