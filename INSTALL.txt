v16.14
------

Patrol pressure rebalanced. Patrol squad size drops from 10x to 6x and patrol
count rises from 3x to 6x, so patrols appear as often as before but in more,
smaller groups.

Current preview settings:

| Setting | Value |
|---|---|
| Reinforcement budget (`cfg+0x78` and `director+0x518B0`) | `0.4x` |
| Enemy reinforcement cooldown clamp (`director+0x399D8`) | `2 s` |
| `cfg+0x164` encounter_cooldown_rate_modifier | `3x` |
| `cfg+0x1A0` patrol_count_max_modifier | `6x` |
| `cfg+0x1DC` patrol_spawn_cooldown_rate_modifier | `3x` |
| `cfg+0x3F8` travelers_max_unit_count_multiplier | `6x` |
| Encounter candidate weighting | cheapest 50% `0.25x`, middle 30% `1.0x`, costliest 20% `4.0x` |
| Timed Patrol/Straggler intervals | `0.0-0.1 s` |
| Nonzero per-type caps and group clamp | `10x` |
| GuardForce / static defenders | native |

The effective `cfg+0x78` override is still forced to the already-scaled director
base, so a positive native override cannot bypass the budget reduction. Timed
Patrol/Straggler intervals remain pinned but are inert on this build, because the
timed scheduler branch is unreachable. Executable code is unchanged throughout.

Why the split moved

6x squad size with 6x patrol count keeps roughly the same total patrol population
as the previous 10x/3x combination while spending far fewer units per group. That
matters because the shared native gate counts individual components: a wave of 11
base units at 10x is up to 110 entities, whereas at 6x it is up to 66. Halving the
per-group peak while doubling how many groups can exist gives the same sustained
patrol pressure with more headroom against the component-448 term.

What to watch

The 448 gate was never reached in the captured vanilla sessions - peak 97 against a
limit of 448 - but 10x patrol waves plus 3x count could have consumed that margin.
With 6x/6x the per-wave peak halves, so this build should stay further from the
gate while feeling similar in volume.

Reading the log
---------------

- p=   Encounter budget current/original. With a native 600 this reads 240.0/600.0.
- o=   effective cfg+0x78 override. Expect 240.00.
- ms=  applied curve scales, expected 3.0/6.0/3.0/6.0.
- mv=  live head float of each scaled curve. With a baseline of 1.0 this reads
       3.00/6.00/3.00/6.00.
- w=   biased/available candidates, or the fallback reason.
- e=, a=, b=, d=, fl=  reinforcement deadline and timed-scheduler gate inputs.
